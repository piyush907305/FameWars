# Release checklist

**Status:** proposed Phase 0 specification, v0.0.0 • 2026-11-09 • Owner: project owner (sole producer). No approval or production readiness implied.

**Content rule:** original fictional archetypes only; no real-person names, likenesses, imitations or voice clones. Every fighter requires `licenseStatus`, provenance and a remote disable key. Licensed additions cannot ship without written permission. See [content and privacy policy](09-legal-and-content-policy.md). All ASSUMPTION IDs resolve in [the register](11-risks-and-open-questions.md).

## Phase 0 acceptance (this delivery)

- [x] Definition docs 01–11, seven proposed ADRs and supporting templates exist.
- [x] No gameplay code/dependencies/remote service/paid signup or prior celebrity assets included.
- [x] Original-only content rule and pending approval status explicit.
- [x] Assumptions and exact Phase 1 questions recorded.
- [ ] Owner approval and Q1–Q8 answered/explicitly deferred.
- [ ] GitHub owner/name/visibility and code licence chosen; remote created later.

Checked boxes mean documentation presence only; they do not certify future implementation, law or asset rights.

## Every playable release (future, all unchecked)

- [ ] Reproducible pinned install/build; sim/content/protocol/client versions recorded.
- [ ] Relevant strict type/lint/schema checks and replay/edge-case tests passed.
- [ ] Human input, CPU and all supported control modes exercised.
- [ ] Match winner, stamina performer and equal-tie behavior match approved rules.
- [ ] Actual model deformation, voice/subtitles and bilingual font/layout approved.
- [ ] Complete commercial provenance and credits; no unknown/licensed-without-permission content.
- [ ] Named device/transfer/memory/thermal evidence attached; unmeasured results not passed.
- [ ] Remote disable, cache expiry, revoked assets and key rotation verified.
- [ ] Age/privacy/consent and data deletion/request routes validated; no SDK before eligibility.
- [ ] Online gate if applicable: server outcomes, network matrix, load measurements, reconnection and abuse.
- [ ] Ads gate if applicable: provider approved, test mode checked, no fight interruption, consent denial/no fill, idempotent verified reward and reporting reconciliation.
- [ ] Legal publisher/contact/policies and applicable India gaming/privacy obligations reviewed before public launch.
- [ ] Budget caps/alerts, rollback pair, logs/retention and incident contact working.
- [ ] Playable staging build, known limitations and release notes reviewed; owner explicitly approves release.

Native distribution additionally requires build/signing/device tests, plugin licences, lifecycle/audio/consent/ads behavior, store age/privacy labels and review approval. A wrapper is not a guaranteed no-change deployment.
